# 用例图绘制说明（多用户版）

本文件只提供手工绘图所需的参与者、用例、关系和布局，不直接生成图。正文推荐使用一张完整用例图，三个模块局部图和 AI 子图可用于分步讲解或答辩备份。

## 1. 系统边界与参与者

系统边界框标题：校园多源消息智能聚合与信息管理系统（UniBrief）。

| 编号 | 参与者 | 类型 | 职责 |
|---|---|---|---|
| A1 | 普通用户 | 主参与者 | 管理自己的渠道、消息、信息、标签、事项和统计 |
| A2 | 系统管理员 | 管理参与者 | 管理普通账号、注册开关、Platform 和 Category |
| A3 | 消息导入适配器 | 外部系统 | 提供统一 JSON/CSV 消息；可选 NapCat OneBot bridge 转换 QQ 消息 |
| A4 | OpenAI-compatible AI 服务 | 外部系统 | 提供模型列表、连接测试和真实消息分析 |

MySQL、React、FastAPI、User、Sender 和 SystemSetting 都不是参与者。User、Sender、SystemSetting 是系统内部数据对象。

边界说明：

- 管理员不属于普通 User 角色，使用独立管理入口。
- 管理员没有查看 Message、InformationItem、Tag、Event 或用户统计的用例。
- 普通用户只能访问自己的私有数据。
- 公开注册是条件用例，由 registration_enabled 控制，默认关闭。

## 3. include / extend 关系

| 来源用例 | 关系 | 目标用例 | 条件/理由 |
|---|---|---|---|
| U01 注册账号 | <<include>> | 校验注册开关 | 后端每次注册都必须确认 registration_enabled=true |
| U06 导入消息 | <<include>> | 校验输入格式 | 每次导入必须执行 |
| U06 导入消息 | <<include>> | 用户范围内消息去重 | 每次导入必须执行 |
| U08 选择 AI 模型 | <<include>> | 加载模型列表 | 正常优先路径 |
| 手工输入模型 ID | <<extend>> | U08 选择 AI 模型 | 模型列表不支持或用户指定其他模型 |
| U10 分析消息 | <<include>> | 指定模型 | 本次未选且无默认模型时不能分析 |
| U10 分析消息 | <<include>> | 校验 AI 输出 | 未校验结果不得写业务表 |
| 自动窗口分析 | <<extend>> | U10 分析消息 | 同一用户、同一 Channel 达 20 条或 5 分钟 |
| U12 查看详情与来源 | <<include>> | 追溯原始 Message | 详情必须能够核对证据 |
| U11 浏览有效信息 | <<include>> | 搜索与组合筛选 | 信息浏览的核心能力 |
| 生成 Event | <<extend>> | 创建/更新信息 | 识别到时间属性时发生 |
| 生成默认提醒 | <<extend>> | 生成 Event | Event 有 Deadline 时原子创建 EventReminder |

图旁结论：

### 4.2 模块二：AI 分析与信息聚合

保留用例：

- 单条分析、手工批量分析、自动窗口分析；
- 识别无用消息；
- 创建/关联/更新 InformationItem；
- 记录 AIAnalysis；
- 生成 Category、Tag、Event；
- 失败后更换模型重试。

图旁注明：候选 InformationItem、Message、Tag 和分析批次必须属于同一用户。

### 4.3 模块三：信息组织与利用

参与者：普通用户。

保留用例：

- 浏览与筛选 InformationItem；
- 查看详情与原始来源；
- 人工修正/归档；
- 查看 Event；
- 查看渠道有效率、Category 分布、Tag 热门度和近期事项。

图旁注明：Category 全局共享且用户只读，Tag 与所有统计结果均为当前用户私有。

## 5. 手工布局

完整图建议使用横向 16:9：

- 左上放系统管理员，连接边界内左列的管理用例。
- 左中放普通用户，连接中间三列普通业务用例。
- 左下放消息导入适配器，只连接导入消息；旁注“JSON/CSV；QQ 可选 NapCat OneBot bridge”。
- 右侧放 AI 服务，连接模型和分析用例。
- 系统边界内分四列：认证与系统管理；来源与导入；AI 与信息聚合；查询与统计。
- 使用浅色分区，避免一条参与者连线穿过全部用例。

图右下角：

> 普通用户的数据彼此隔离。管理员只维护账号与全局字典，不进入用户私有内容。

## 6. 关键用例规约

### U01 注册账号

- 前置条件：registration_enabled=true。
- 主场景：填写唯一用户名、显示名和密码 -> 校验 -> Argon2id 哈希 -> 创建 ACTIVE User。
- 备选场景：注册关闭返回明确状态；用户名重复返回冲突。
- 后置条件：只创建普通 User，不产生业务数据。

### U06 导入消息

- 前置条件：普通用户已登录，平台 ACTIVE，输入符合 Adapter 格式。
- 主场景：从会话取得 user_id -> 匹配当前用户 Channel/Sender -> 按 (user_id, channel_id, external_id) 去重 -> 写 Message/附件 -> 返回新增、重复和失败数。
- 备选场景：格式错误逐项报告；并发唯一键冲突按重复处理。
- 后置条件：新 Message 为 PENDING，不能归属其他用户。

### U10 分析消息

- 前置条件：Message 属于当前用户，模型可用。
- 主场景：标记 PROCESSING -> 查询同用户候选 -> 事务外调用 AI -> 校验 -> 短事务写分析、信息、关联、分类、标签、事项和状态。
- 备选场景：无用消息进入 IGNORED；失败进入 FAILED；其他用户 ID 按不存在处理。
- 后置条件：原文始终保留，成功结果全部原子提交。

### U12 查看详情与来源

- 前置条件：InformationItem 属于当前用户。
- 主场景：返回摘要、共享 Category、私有 Tag、Event 和关联 Message。
- 备选场景：无 Event 正常显示；其他用户 ID 返回 404。
- 后置条件：只读，不改变数据。

### M06 控制注册开关

- 前置条件：独立管理员会话有效。
- 主场景：读取非敏感设置 -> 修改 registration_enabled -> 严格校验 BOOLEAN -> 保存。
- 安全要求：设置接口不得返回 admin_password_hash 或其他 SECRET value_text。

## 7. 绘图自检

- 是否有四个参与者，并区分普通用户与系统管理员？
- 是否没有把数据库、框架、User、Sender 或 SystemSetting 画成演员？
- 是否表现注册是受开关控制的条件用例？
- 管理员是否没有查看用户 Message/InformationItem/Tag/Event 的用例？
- 普通业务是否覆盖导入、AI、信息、事项、追溯和统计？
- 是否明确自动分析窗口不跨用户或 Channel？
- include 箭头是否指向被包含用例，extend 是否指向被扩展用例？
- 是否没有多级 RBAC 或用户间共享？
