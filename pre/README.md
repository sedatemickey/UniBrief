# 课堂展示材料索引

本目录保存需求分析、系统架构、数据库设计、第一次展示讲稿/PPT，以及最终系统演示可复用的图表材料。

## 当前状态

截至 2026-09-01，Phase 0–5 已完成，正在执行 Phase 6 收尾。16 张核心表、附件、EventReminder、用户隔离、真实 OpenAI-compatible Provider、统计高级对象、Web UI 和固定 demo dataset 已实现；真实 AI 与 NapCat 的成功联调仍分别依赖合法服务配置和第三方框架搭建。

- `00`–`04`：早期单用户历史材料，已标记 Superseded，不得作为正式口径。
- `05`–`10`、`13`：多用户版绘图、流程和答辩说明，应与当前代码保持同步。
- `11`、`12`：第一次展示历史讲稿/PPT，保留当时“设计阶段”的叙述，不能直接用来描述当前实现状态。
- `90_演讲稿.md`：当前完整讲解稿；最终操作演示顺序以 `docs/DEMO_SCRIPT.md` 为准。

## 推荐使用顺序

1. 先读 `AGENTS.md`、`docs/COURSE_REQUIREMENTS.md`、`docs/ARCHITECTURE.md`、`docs/DATABASE.md`。
2. 用 `docs/DATA_DICTIONARY.md` 和 `docs/ER_MAPPING.md` 校对字段、键和基数。
3. 用 `05`–`09`、`13` 维护用例图、流程图和 ER/模型图。
4. 第一次设计展示使用 `11`/`12`；第二次系统演示使用 `docs/DEMO_SCRIPT.md`。
5. 展示前按 `10_答辩准备与讲解建议.md`、`docs/SCREENSHOT_CHECKLIST.md` 自检。

## 正式口径

- 16 张核心表；
- User 是系统普通账号，Sender 是外部消息发送者；管理员不作为 User 角色；
- Message ↔ InformationItem、InformationItem ↔ Tag 均通过关联表，跨用户关系由复合外键阻止；
- InformationItem 1:0..1 Event，Event 1:0..1 EventReminder；
- 附件数据库保存元数据与相对存储键，文件保存在受控本地目录；
- 默认提醒由 Deadline 提前 24 小时派生，支持自定义、关闭和已读；
- 所有正式实现状态与测试结果以 `docs/PROGRESS.md`、`docs/ACCEPTANCE.md` 为准。
