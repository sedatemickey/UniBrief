# 多用户版第一次展示 PPT 大纲

## 总体要求

- 16 页，约 10 分钟。
- 主线：现实问题 -> 三个模块 -> 完整用例图/ER 图 -> 数据库约束与非功能需求。
- 不放技术栈介绍页，不展开接口路径或代码。
- ER 图实体框只写英文表名；中文解释放在页边和演讲备注。
- 旧版单用户材料仅作历史参考，本文件以多用户设计为准。

## 逐页内容

### 1. 封面

标题、课程、姓名、学号、日期。副标题：需求分析与多用户数据库设计。

### 2. 灵感：一条不断变化的作业通知

用三段时间线占位：发布要求 -> 补充附件 -> 修改截止时间。中间穿插闲聊，突出“最终版本难找”。

### 3. 四个具体问题

多平台分散、闲聊淹没、通知持续变化、用户数据需要隔离。用“现状/影响”短表，不写长段落。

### 4. 功能需求与边界

三栏展示三个模块。页脚列出边界：不逆向平台协议、不做团队共享、不做多级 RBAC、管理员不查看私有内容。

### 5. 模块一：用户、来源与归档用例

局部用例图：管理员创建用户/控制注册；用户登录、管理 Channel、导入和查询 Message；Adapter 提供 JSON/CSV 数据，QQ 可选通过 NapCat OneBot bridge 转换后导入。

### 6. 模块一：局部 ER

实体：User、SystemSetting、Platform、Channel、Sender、Message、MessageAttachment。突出 User 归属和 Sender 与 User 的区别。

### 7. 模块二：AI 分析与聚合用例

单条分析、批量分析、判断有效性、创建/关联/更新、失败重试。用角标标出“同用户、同 Channel 批量”。

### 8. 模块二：局部 ER

实体：User、Message、AIAnalysis、MessageInformation、InformationItem。用作业通知、补充、纠正解释 M:N。

### 9. 模块三：组织与利用用例

浏览筛选、查看详情和来源、查看 Event、统计。Category 共享，Tag 私有。

### 10. 模块三：局部 ER

实体：User、InformationItem、Category、InformationCategory、Tag、InformationTag、Event。

### 11. 完整用例图

四个参与者：普通用户、系统管理员、消息导入适配器、OpenAI-compatible AI 服务。管理员区域不得出现用户私有内容用例。

### 12. 完整 ER 图

16 张表总览，按账号设置、来源消息、分析信息、组织事项四组配色。只保留主键、外键和少量代表字段；标出 InformationItem.version 与 EventReminder。

### 13. 三个模块的数据接力

横向文字图：User -> Message -> AIAnalysis -> InformationItem -> Category/Tag/Event -> 查询统计。两条回看箭头表示来源追溯和统计复核。

### 14. 数据库如何保证正确

四组内容：主外键、用户内唯一约束、同用户复合外键、用户级索引。右侧放一个“甲用户 Message 不能连接乙用户 InformationItem”的反例。

### 15. 性能与其他需求

- AI：同一用户、同一 Channel，20 条或 5 分钟触发。
- 性能：分页、组合索引、数据库统计。
- 可靠性：幂等、失败保留原文、事务回滚。
- 安全：Argon2id、HttpOnly Cookie、CSRF、敏感设置保护。
- 易用性：注册开关、错误提示、中文界面。

### 16. 总结

三句话：原文有证据、信息有关系、用户有边界。第一次展示版本可保留“当前为设计阶段”；若用于最终报告，改为“设计已通过 Alembic 迁移、约束测试和系统流程验证”，并引用 `docs/PROGRESS.md`。
