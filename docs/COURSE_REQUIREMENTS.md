# 数据库课程设计：2026 课程要求摘要

来源：教师提供的《数据库课程设计题目及要求-2026.pptx》。

> 本文件只总结课件中明确给出的课程定位、硬性要求、评分点和提交要求。
> 若后续教师发布更新通知，以教师最新通知为准。

## 1. 课程定位与目标

课程设计的定位不是“做一个普通网页”或“调用一个 AI API”，而是：

- 在掌握数据库理论后，将数据库与软件开发结合；
- 使用主流 DBMS 和自选高级程序设计语言；
- 实现一个**完整的、以数据库为核心的应用系统**；
- 开发工具与系统体系结构可以自选；
- 项目应具有“产品化导向”，并走完整的软件开发流程。

课件明确要求掌握完整流程：

1. 需求分析
2. 数据库设计
3. 应用程序设计
4. 编码
5. 测试

数据库相关能力包括：

- 数据库连接
- SQL
- 完整性约束
- 索引
- 视图
- 触发器
- 存储过程等数据库对象的综合运用
- 关系数据库理论
- 数据库设计
- 事务

因此本项目必须始终保持：
**数据库是主角，AI 是数据库应用中的一个处理模块。**

## 2. 课件明确的硬性项目要求

### 选题
- 题目可以自选。
- **不能做：**
  - 宾馆/酒店系统
  - 学生选课系统
  - 图书馆系统

当前项目“校园多源消息智能聚合与信息管理系统”属于自选题，不属于上述禁题。

### 数据表
- **数据表不能少于 5 个。**

当前设计有 13 张核心表，满足这一最低要求。

### 技术选择
- 开发工具自选。
- DBMS 可以使用机房 Oracle，也可以自选其他 DBMS。
- 课件**推荐 MySQL**。
- 软件架构自选，但必须保证在规定时间内完成系统。

本项目因此使用 MySQL，并优先控制工程复杂度。

### 独立完成
- 要求独立完成。
- 雷同系统或雷同报告记 0 分。

因此：
- 演示数据必须使用自行生成的 synthetic data；
- 不复制其他课程设计代码或报告；
- Codex 只作为开发辅助工具，最终系统结构、设计说明、答辩内容必须能够由项目作者本人解释。

## 3. 第一次展示：需求分析与数据库设计，30 分

评分构成：

- 功能方面需求分析：10 分
- 性能及其他需求分析：5 分
- 数据库设计：15 分

课件强调第一次展示重点：

- 需求分析
- 用例图
- ER 图
- 实体
- 实体之间的各种关系

因此项目实现时必须同步沉淀可用于第一次 PPT 的材料：

### 必须能输出
- 项目背景与问题定义
- 系统边界
- 功能需求
- 非功能需求
- 核心业务流程
- 用例图
- ER 图
- 每个实体的用途
- 表间 1:1 / 1:N / M:N 联系及业务触发场景
- 逻辑关系模式
- 主键、外键、唯一约束说明
- 关键索引和事务设计

Codex 在修改数据库模型时，不得只改代码而不同步 `docs/DATABASE.md`。

## 4. 第二次展示：系统演示，30 分

课堂演示要求：

- 演示系统中**最有代表性的完整业务流程**；
- 登录、修改密码、退出等功能**不算代表性业务流程**；
- 必须演示**至少 3 个统计功能**。

评分：

- 功能：16 分
- 健壮性：8 分
- 易用性：6 分

数据量要求：

- **演示实体数据不能少于 30 条**
- **关联关系数据不能少于 200 条**

因此当前项目演示必须至少覆盖：

### 代表性完整业务流程
消息导入
→ 原始 Message 入库
→ 调用真实 OpenAI-compatible AI
→ AIAnalysis 保存
→ 判断是否有用
→ 创建/关联/更新 InformationItem
→ Category / Tag 结构化
→ 有时间信息则生成 Event
→ 前端展示
→ 从 InformationItem 追溯原始 Message

### 至少 3 个统计功能
本项目固定实现：

1. 各 Channel 的消息总数、有效消息数、有效率
2. Category 信息分布
3. Tag 热门度 Top N

建议额外实现：

4. 未来 7 天截止 Event 数量/列表

### 健壮性重点
必须能演示或测试：

- 重复消息导入不会产生重复数据
- AI API 请求失败
- AI 返回非法 JSON / 缺字段
- API 超时
- 模型不可用
- 无用闲聊被过滤
- 数据库事务失败时回滚
- 空列表/无统计数据
- 同一 InformationItem 被多条 Message 支持

## 5. 课程设计报告：40 分

报告评分构成：

- 数据库概念设计和逻辑设计：20 分
- 数据库规划、系统定义、需求分析：15 分
- 物理设计和其他：5 分

因此报告素材应覆盖：

### 数据库规划 / 系统定义 / 需求分析
- 任务陈述
- 项目目标
- 系统边界
- 用户/使用场景（本项目为单用户）
- 数据需求
- 业务/事务需求
- 非功能需求

### 概念设计 / 逻辑设计
- ER 图
- 实体与联系
- 数据字典
- 关系模式
- 主键 / 外键
- M:N 关联表
- 规范化设计说明

### 物理设计及其他
- MySQL 选型
- 索引
- 视图
- 完整性约束
- 事务
- 触发器/存储过程等数据库对象（在设计合理和工期允许的情况下综合运用）
- 安全与敏感配置处理
- 测试
- 运行截图

> 注意：课件把视图、触发器、存储过程等列为课程目标中的“综合运用”内容，
> 但评分页没有把“每一种必须单独实现”写成独立硬性分项。
> 因此实现时优先保证设计合理、可解释、可演示，不为了凑数量滥用数据库对象。

## 6. 时间与提交

课件给出的安排：

- 周一、周二上午：PPT 展示
- 周三、周四、周五上午：系统演示
- 课程结束后提交课程设计报告
- 课件注明报告提交截止日期：10 月 8 日

报告：
- 按规定格式撰写；
- 文件命名形式：
  `学号-姓名-数据库课程设计报告.pdf`
- 上传到教师指定的 FTP / 班级目录。

仓库中不要硬编码 FTP 账号密码或其他提交凭据。

## 7. 对本项目开发优先级的直接约束

若工期不足，优先级必须是：

1. 数据库结构和关系正确
2. 需求分析与 ER 图能解释
3. 完整业务流程可跑通
4. 真实 AI API 可用且异常可处理
5. 至少 3 个统计功能
6. 演示数据量达到要求
7. 健壮性
8. 易用性
9. UI 美化
10. 额外扩展功能

不得为了做 UI 动画、复杂 Agent 或真实 QQ/微信逆向接入而牺牲上述评分项。
