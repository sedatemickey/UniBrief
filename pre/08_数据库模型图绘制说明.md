# 数据库模型图绘制说明（多用户版）

## 1. 图的定位与图例

数据库模型图展示 MySQL 中计划落地的 16 张表、字段、主外键、唯一约束和关键索引。ER 图讲业务概念，模型图证明关系如何由字段和约束实现。

数据库：MySQL 8.x；字符集：utf8mb4；表与字段：snake_case。

图例：

- PK：主键
- FK：外键
- UK：唯一约束组成列
- IDX：普通索引组成列
- NN：NOT NULL
- PK(1)、PK(2)：联合主键顺序
- FK-C：复合外键组成列
- SENSITIVE：禁止通过普通 API 返回

## 2. 16 张表字段框

### 2.1 user

用途：普通登录用户，不是外部消息 Sender。

| 标记 | 字段 | 类型 | 可空/默认 | 说明 |
|---|---|---|---|---|
| PK | id | BIGINT | NN | 主键 |
| UK | username | VARCHAR(64) | NN | 登录名，全局唯一 |
|  | display_name | VARCHAR(128) | NN | 显示名称 |
| SENSITIVE | password_hash | VARCHAR(255) | NN | Argon2id 哈希 |
| IDX | status | VARCHAR(32) | NN / ACTIVE | ACTIVE、DISABLED |
|  | session_version | INT UNSIGNED | NN / 1 | 旧会话失效版本 |
|  | last_login_at | DATETIME | NULL | 最近登录时间 |
|  | created_at | DATETIME | NN | 创建时间 |
|  | updated_at | DATETIME | NN | 更新时间 |

### 2.2 system_setting

用途：少量、受控的系统级杂项设置。

| 标记 | 字段 | 类型 | 可空/默认 | 说明 |
|---|---|---|---|---|
| PK | setting_key | VARCHAR(128) | NN | 白名单设置键 |
| SENSITIVE 可选 | value_text | TEXT | NN | 统一文本存储，按类型严格解析 |
|  | value_type | VARCHAR(32) | NN | BOOLEAN、INTEGER、STRING、SECRET |
|  | is_sensitive | BOOLEAN | NN / FALSE | 敏感值标记 |
|  | description | VARCHAR(255) | NULL | 设置说明 |
|  | updated_at | DATETIME | NN | 更新时间 |

首批键：

| setting_key | value_type | is_sensitive |
|---|---|---:|
| registration_enabled | BOOLEAN | false |
| admin_password_hash | SECRET | true |
| admin_session_version | INTEGER | true |

绘图注释：SystemSetting 无业务外键；未知键不能由 API 创建；AI_API_KEY 不进入此表。

### 2.6 message

用途：保存用户的原始消息，是核心大表。

| 标记 | 字段 | 类型 | 可空/默认 | 说明 |
|---|---|---|---|---|
| PK, UK(2) | id | BIGINT | NN | 主键 |
| FK, UK(1), FK-C, IDX | user_id | BIGINT | NN | -> user.id |
| FK-C, UK(2), IDX | channel_id | BIGINT | NN | 与 user_id 共同引用 channel |
| FK-C, IDX | sender_id | BIGINT | NN | 与 user_id 共同引用 sender |
| UK(3) | external_id | VARCHAR(191) | NN | 渠道内消息 ID |
|  | content | TEXT | NN | 原文 |
| IDX | sent_at | DATETIME | NN | 发送时间 |
| IDX | ingested_at | DATETIME | NN | 接入时间 |
| IDX | process_status | VARCHAR(32) | NN / PENDING | 处理状态 |

约束：

- UNIQUE(user_id, channel_id, external_id)
- UNIQUE(user_id, id)，供 MessageInformation 复合外键引用
- FK(user_id, channel_id) -> channel(user_id, id)
- FK(user_id, sender_id) -> sender(user_id, id)

关键索引：

- INDEX(user_id, channel_id, sent_at)
- INDEX(user_id, sender_id, sent_at)
- INDEX(user_id, process_status, ingested_at)

### 2.8 ai_analysis

|  | model_name | VARCHAR(128) | NN | 实际模型 |
|  | status | VARCHAR(32) | NN | SUCCEEDED/FAILED |
|  | useful | BOOLEAN | NULL | 是否有用 |
|  | importance | TINYINT | NULL | 重要度 |

### 2.9 information_item

### 2.10 message_information

## 4. 推荐模型图布局

### 4.1 单页总览

- 左上：user；其下独立放 system_setting。
- 左侧：platform，上下连接 channel、sender。
- 中左：message；上方 ai_analysis，下方 message_attachment。
- 中间：message_information。
- 中右：information_item。
- 右上：category 与 information_category。
- 右中：tag 与 information_tag。
- 右下：event、event_reminder。

用虚线大区分“全局共享”和“用户私有”。复合外键使用较粗或双线，并在图例写 FK-C。

### 4.2 拆成三页

如果单页字段过密：

1. 账号与来源：user、system_setting、platform、channel、sender、message、attachment。
2. 分析与聚合：user、message、ai_analysis、message_information、information_item。
3. 组织与事项：user、information_item、category、information_category、tag、information_tag、event、event_reminder。

每页重复出现的 User、Message、InformationItem 只作为连接锚点，不代表重复建表。

## 5. 唯一约束与业务规则

| 唯一约束 | 防止的问题 | 范围 |
|---|---|---|
| user.username | 重复登录名 | 全局 |
| platform.name | 重复平台 | 全局 |
| channel(user_id, platform_id, external_id) | 同一用户重复渠道 | 用户+平台 |
| sender(user_id, platform_id, external_id) | 同一用户重复发送者 | 用户+平台 |
| message(user_id, channel_id, external_id) | 同一用户重复导入消息 | 用户+渠道 |
| category.name | 重复稳定分类 | 全局 |
| tag(user_id, name) | 同一用户重复标签 | 用户 |
| event.information_id | 一个信息生成多个 Event | InformationItem |
| 三张关联表联合主键 | 同一关系重复插入 | 关系对 |

UNIQUE(user_id, id) 属于复合外键支撑约束，不是业务自然键。

## 6. 索引设计

| 索引 | 查询 | 字段顺序理由 |
|---|---|---|
| message(user_id, channel_id, sent_at) | 当前用户某渠道时间范围消息 | 先用户隔离，再等值渠道，最后时间 |
| message(user_id, sender_id, sent_at) | 当前用户某发送者消息 | 同上 |
| message(user_id, process_status, ingested_at) | 当前用户待处理/失败消息 | 用户、状态、调度时间 |
| ai_analysis(message_id, analyzed_at) | 某消息分析历史 | 先消息，再时间 |
| information_item(user_id, status, importance, created_at) | 当前用户信息流 | 用户、状态、重要度、时间 |
| event(deadline) | 截止时间范围 | 通过 InformationItem 连接后范围过滤 |
| event(event_status, deadline) | 某状态临近事项 | 状态后接时间 |

实现后必须使用 EXPLAIN 验证，不以“建过索引”代替查询验证。

## 7. SystemSetting 使用边界

- setting_key 是白名单主键。
- value_type 决定严格解析方式。
- is_sensitive=true 的 value_text 不通过普通读取接口返回。
- 管理员改密同时更新 admin_password_hash 和 admin_session_version。
- registration_enabled 默认 false。
- 用户偏好、Tag、Category、消息列表、AI Key 都不能放入此表。

## 8. 规范化与多用户完整性

- Platform、Channel、Sender 分离，Message 不重复保存名称。
- Category、Tag 不存成逗号字符串；附件不存成 JSON 数组。
- AI raw_result 仅为审计副本，不替代业务关系。
- User 直接标识主要私有实体归属；子实体通过父实体继承。
- MessageInformation 与 InformationTag 使用复合外键，把“同一用户”从应用规则提升为数据库约束。
- Category 共享而 Tag 私有，避免重复固定字典，同时保护用户主题边界。

## 9. 数据库高级对象

| 类型 | 名称 | 多用户要求 |
|---|---|---|
| View | v_upcoming_events | 输出 user_id，调用时过滤 |
| View | v_channel_effectiveness | 按 user_id、Channel 聚合 |
| View | v_category_statistics | 按 user_id、Category 聚合 |
| 可选 View | v_tag_popularity | 只统计用户私有 Tag |
| Trigger | InformationItem 更新时间 | 不改变 user_id |
| Stored Procedure（必须） | sp_channel_statistics | 参数包含 p_user_id、p_start、p_end |

Service 调用存储过程时只能传入当前会话 user_id。

## 10. 删除与安全策略

- User 使用 DISABLED，不物理删除；停用时 session_version + 1。
- Platform、Category 被引用后只停用。
- Message 保留原始证据，InformationItem 使用 ARCHIVED。
- 管理员不能通过管理 API 查询私有业务表。
- SystemSetting 敏感项、User.password_hash 和 AI Key 不出现在图表样例数据、日志或 API 响应中。
