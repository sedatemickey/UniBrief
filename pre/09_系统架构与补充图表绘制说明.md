## 2. 多用户系统边界图

### 2.1 中心系统框

标题：UniBrief 校园多源消息智能聚合与信息管理系统。

框内能力：

- 用户认证与私有数据空间
- 来源归一化与原文保存
- AI 结构化分析
- 有效信息聚合
- 分类、标签与事项
- 查询、追溯与统计
- 管理员账号和全局字典管理

### 2.2 外部对象

| 对象 | 流入系统 | 系统返回 |
|---|---|---|
| 普通用户 | 登录、导入、模型选择、查询和修正 | 私有消息、信息、事项和统计 |
| 系统管理员 | 管理密码、用户管理、注册开关、全局字典操作 | 管理结果，不含用户私有内容 |
| 消息导入适配器 | JSON/CSV 统一消息；NapCat OneBot bridge 可选转换 QQ 消息 | 导入校验结果 |
| OpenAI-compatible AI | 模型列表、分析响应或错误 | 测试和分析请求 |

### 2.3 边界外注释

- 不在 UniBrief 内逆向 QQ、微信、钉钉协议；NapCat 是独立第三方协议端，UniBrief 只消费其 OneBot 消息事件。
- 不做团队空间、用户间共享或多级 RBAC。
- 管理员不能查看用户 Message、InformationItem、Tag、Event。
- 不做自动回复、RAG、向量数据库、多 Agent 和移动端 App。

结论：

> 系统从统一消息格式开始负责，并以认证用户为每条私有数据确定归属。

## 3. 总体系统架构图

### 3.1 分层

从上到下画五层：

1. 表现层
   - 普通用户 React 应用
   - 独立管理员页面
2. API 与安全层
   - FastAPI REST
   - 普通/管理员 Cookie
   - CSRF
   - Pydantic 校验
3. 业务层
   - auth、admin、setting
   - platform、sender、ingestion
   - analysis、information、classification
   - event、statistics、search
4. 访问与集成层
   - Repository
   - JSON/CSV Message Adapter
   - 可选 NapCat OneBot bridge
   - OpenAICompatibleProvider
   - AI 结果解析器
5. 数据层
   - MySQL 16 表
   - Alembic
   - View、Trigger、Stored Procedure

### 3.2 主要箭头

- 普通 UI -> Auth Middleware -> 业务 API：Cookie + CSRF。
- 管理员 UI -> Admin Auth -> Admin Service：独立 Cookie 和 /admin 路径。
- Service -> Repository -> MySQL：所有普通查询携带当前 user_id。
- Import -> Adapter -> Ingestion：统一输入。
- Analysis -> Provider -> 外部 AI：事务外 HTTP。
- Statistics -> 用户级 View/查询 -> 图表。

### 3.3 SystemSetting 在架构中的位置

- 位于 MySQL 数据层。
- SettingService 负责白名单、类型转换和敏感值保护。
- AuthService 只读取 registration_enabled。
- AdminAuth 只读取/更新 admin_password_hash 与 admin_session_version。
- 普通配置 API 不直接暴露 value_text。

### 3.4 不应画入

Redis、Kafka、Celery、向量数据库、微服务、平台协议逆向器和运行时 Mock AI 都不属于当前设计。

## 4. 数据生命周期与用户边界图

从左到右画：

1. 身份与配置：User、SystemSetting。
2. 共享字典：Platform、Category。
3. 私有来源：Channel、Sender。
4. 原始证据：Message、MessageAttachment。
5. 分析记录：AIAnalysis。
6. 有效信息：MessageInformation、InformationItem。
7. 私有组织与时间：Tag、InformationTag、Event；InformationCategory 连接共享 Category。
8. 消费：信息流、搜索、事项、统计、来源追溯。

在 User 下方画一条横向“user_id 私有边界”，覆盖 Channel、Sender、Message、InformationItem、Tag 和用户统计。

回看箭头：

- InformationItem -> MessageInformation -> Message：追溯原文。
- 统计 -> 用户级 View/基础表：统计可复核。

结论：

> 原始数据不被 AI 覆盖，结构化信息不脱离证据，私有数据不跨越 User 边界。

## 5. 数据流图 DFD

### 5.1 0 层 DFD

外部实体：

- E1 普通用户
- E2 系统管理员
- E3 消息导入适配器
- E4 AI 服务

中心处理：P0 UniBrief。

数据流：

- E1 -> P0：凭据、消息文件、模型选择、查询和修正。
- P0 -> E1：认证结果、私有消息、信息、事项、统计和错误。
- E2 -> P0：管理凭据、账号操作、设置和字典操作。
- P0 -> E2：管理结果、非敏感设置状态。
- E3 -> P0：统一消息与附件。
- P0 <-> E4：模型、测试和分析请求/响应。

0 层不画表。

### 5.2 1 层 DFD

处理：

- P1 用户与管理员认证
- P2 系统设置和全局字典管理
- P3 私有来源与消息导入
- P4 AI 分析与校验
- P5 有效信息聚合
- P6 查询、事项与统计

数据存储：

- D1 账号设置：User、SystemSetting
- D2 全局字典：Platform、Category
- D3 私有来源：Channel、Sender
- D4 原始消息：Message、MessageAttachment
- D5 分析记录：AIAnalysis
- D6 有效信息：InformationItem、MessageInformation
- D7 标签事项：Tag、InformationCategory、InformationTag、Event

关键流向：

1. E1/E2 <-> P1 <-> D1。
2. E2 <-> P2 <-> D1/D2。
3. E3/E1 -> P3 -> D3/D4。
4. P4 读取当前用户 D4/D6，与 E4 交互，写 D5。
5. P4 -> P5 -> D6/D7。
6. E1 <-> P6 <-> D2/D3/D4/D6/D7。

每条私有数据流旁可标小字“current user only”。

## 6. 认证与注册状态图

### 6.1 User 状态

- ACTIVE：允许登录和使用业务功能。
- DISABLED：拒绝登录和会话访问，数据保留。

转换：

- 创建或注册成功 -> ACTIVE。
- 管理员停用 -> DISABLED，同时 session_version + 1。
- 管理员重新启用 -> ACTIVE。
- 用户改密/管理员重置 -> 状态不变，session_version + 1。

### 6.2 注册开关

- CLOSED：registration_enabled=false，注册接口返回关闭状态。
- OPEN：registration_enabled=true，允许创建普通 User。

只有管理员可以切换。前端是否显示注册入口不能代替后端检查。

### 6.3 管理员凭据

管理员不作为 User 状态。管理员改密时更新 SystemSetting 中的密码哈希，并递增 admin_session_version。

## 7. Message 状态图

状态：PENDING、PROCESSING、PROCESSED、IGNORED、FAILED。

| 起始 | 事件 | 目标 |
|---|---|---|
| 新建 | 当前用户导入成功 | PENDING |
| PENDING | 手动或窗口触发分析 | PROCESSING |
| PROCESSING | 有效结果原子提交 | PROCESSED |
| PROCESSING | useful=false | IGNORED |
| PROCESSING | AI/校验/数据库失败 | FAILED |
| FAILED | 当前用户更换模型或重试 | PROCESSING |

状态转换前必须验证 Message 属于当前用户。

## 8. Event 状态图

状态：UPCOMING、ONGOING、COMPLETED、EXPIRED、CANCELLED。

- 新建 -> UPCOMING 或 ONGOING。
- UPCOMING -> ONGOING。
- UPCOMING/ONGOING -> COMPLETED。
- UPCOMING/ONGOING -> CANCELLED。
- 未完成且超过 deadline -> EXPIRED。

自动转换由任务还是查询时计算尚未定稿，图中用虚线标“实现阶段确定”。

## 9. 普通用户认证时序图

参与者：User、React UI、Auth API、Auth Service、MySQL。

登录：

1. UI 先读取 registration-status 决定是否显示注册入口。
2. User 提交 username + password。
3. Service 查询 User，校验 ACTIVE 与 Argon2id。
4. 更新 last_login_at。
5. 签发包含 user_id、session_version 的 HttpOnly Cookie。
6. 后续请求校验 Cookie、CSRF、User.status 和 session_version。

改密：

1. 校验旧密码。
2. 写新 password_hash，session_version + 1。
3. 清除旧 Cookie，要求重新登录。

越权：

- 请求资源时 Repository 使用会话 user_id。
- 查不到统一返回 404。

## 10. 管理员认证与设置时序图

参与者：Administrator、Admin UI、Admin API、Admin Service、Setting Service、MySQL。

1. 管理员只提交 password。
2. Setting Service 读取 admin_password_hash，普通日志不记录值。
3. 校验成功后读取 admin_session_version。
4. 签发独立管理员 HttpOnly Cookie。
5. 管理员修改 registration_enabled 时，Setting Service 校验 BOOLEAN 后更新。
6. 管理员读取设置时，只返回非敏感值和敏感项“已配置/未配置”。
7. 管理员改密时同时写新哈希并递增管理员会话版本。

管理 Cookie 不能调用普通私有内容 API；普通 Cookie 不能调用 /admin。

## 11. AI 分析事务时序图

参与者：User、UI、Message API、Analysis Service、MySQL、OpenAI Provider。

正常时序：

1. User 选择模型并分析自己的 Message。
2. API 从 Cookie 得到 user_id，不接受请求体 user_id。
3. Service 按 (user_id, message_id) 查 Message。
4. 更新 PROCESSING 并提交。
5. 查询同用户近期候选。
6. 事务外调用 Provider。
7. Pydantic 校验结果。
8. 开启短事务。
9. 写 AIAnalysis、同用户 InformationItem/MessageInformation、共享 Category、私有 Tag、Event 和最终状态。
10. commit 并返回。

异常片段：

- AI/校验失败：不写业务结果，独立写 FAILED。
- 结果事务失败：rollback，再写 FAILED。
- 其他用户 Message ID：查询不到，返回 404，不调用 AI。

## 12. AI 双阈值窗口图

分组键：(user_id, channel_id)。

流程：

1. PENDING Message 加入对应分组。
2. count >= 20？是则触发。
3. 否则 oldest_wait >= 5 minutes？是则触发。
4. 否则继续等待。
5. 触发前重新验证同用户、同 Channel。
6. 一次调用可分析多条，但结果逐 Message 保存。

不画独立 Batch 表、队列服务或跨 Channel 聚合。

## 13. 需求到数据追踪矩阵

| 需求 | 主要对象 | 关键约束 |
|---|---|---|
| 登录与数据归属 | User | username UNIQUE、status、session_version |
| 管理密码与注册开关 | SystemSetting | 设置键白名单、类型与敏感标记 |
| 全局平台/分类 | Platform、Category | name UNIQUE、受控停用 |
| 私有来源 | Channel、Sender | user_id + platform_id + external_id UNIQUE |
| 原文与去重 | Message、Attachment | user_id 归属、用户+渠道内去重 |
| 多次 AI 分析 | AIAnalysis | Message 1:N |
| 信息聚合 | InformationItem、MessageInformation | 同用户 M:N 复合外键 |
| 分类与私有主题 | Category、Tag、关联表 | Category 共享、Tag 用户内唯一 |
| 截止事项 | Event | information_id FK + UNIQUE |
| 用户级统计 | View/基础表 | 所有口径包含 user_id |

## 15. 统计图表设计

### 15.1 渠道有效率

- 分组柱状图 + 有效率折线。
- 数据：当前用户 Channel 的总消息数、有效 Message 数、有效率。
- 有效消息按至少存在一条 MessageInformation 的 DISTINCT message_id 统计。

### 15.2 Category 分布

- 排序水平条形图。
- Category 全局共享，但计数只统计当前用户 InformationItem。

### 15.3 Tag 热门度

- Top N 水平条形图。
- Tag 本身属于当前用户，按关联 InformationItem 次数统计。

### 15.4 未来事项

- 时间轴或紧凑列表。
- Event 通过 InformationItem 限定当前用户。

图表不得显示跨用户汇总，也不要用无法解释来源的“漂亮数字”。
